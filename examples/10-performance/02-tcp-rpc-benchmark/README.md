# TCP RPC 基准

该基准通过真实回环 TCP Node 执行生成客户端 Await RPC，覆盖连接、帧编解码和传输调度；它不依赖 etcd、NATS 或 Docker。

## 运行

执行 `run.bat` 或 `./run.sh`。测试会临时监听本机端口并在结束后关闭。若端口被安全软件或其他进程占用，请先解决环境问题再比较数据。

## 如何阅读结果

除 `ns/op`、`B/op`、`allocs/op` 外，还应关注不同 `-cpu` 或并发条件下的变化。回环 TCP 只说明框架传输开销，不能等同于真实跨机器延迟、交换机拥塞或 TLS 成本。

## 可修改实验

保持测试提交和 Go 版本一致，分别运行本地、TCP、NATS 三个基准后再比较。不要把一次异常低/高的结果直接用于容量承诺。
