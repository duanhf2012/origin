# Origin 第三版 M3 基础配置库实施计划

> 计划状态：已完成并通过验收
> 创建日期：2026-07-26
> 对应里程碑：[M3 基础配置库里程碑设计](../design/milestones/M3-基础配置库里程碑设计.md)

## 1. 实施目标

实现公开 `config` 包，通过唯一入口 `LoadDir(dir, dst)` 递归加载标准 JSON/YAML 配置目录，完成来源可定位的解析、安全环境变量展开、确定性合并和严格强类型解码。

M3 同时提供统一的 `Duration` 与 `ByteSize` 类型，但不接入 Application、Node、Service、RPC、Discovery、热更新或环境配置覆盖层。

## 2. 实施步骤

1. 固定 `github.com/goccy/go-yaml v1.19.2`，建立公开 `config` 包；
2. 实现目录参数校验、递归扫描、路径规范化、稳定排序及符号链接边界；
3. 使用 `encoding/json` 验证严格 JSON，使用 goccy AST 解析 JSON/YAML 并保留文件、行、列；
4. 转换为调用期内部只读配置树，校验根 Mapping、单文档和字符串 Key；
5. 在字符串 Scalar 上安全展开 `${NAME}`，区分未定义变量与已定义空值，并确保错误不泄露变量值；
6. 实现 Mapping 递归合并、Sequence 稳定追加及重复 Scalar/Null/节点类型冲突错误；
7. 实现零 Tag 的 `snake_case` 字段映射、可选 `json` Tag、匿名嵌入、未知字段拒绝和无部分成功解码；
8. 实现公开 `Duration`、`ByteSize` 的严格语法、转换方法和溢出检查；
9. 补齐单元测试、Fuzz 种子、Benchmark 和配置 `testdata`；
10. 执行质量门禁、记录性能基线、回写验收结果并提交 M3。

## 3. 实现边界

- 公开 API 只有 `LoadDir`、`Duration`、`ByteSize` 及其只读转换方法；
- 不公开 Loader、Snapshot、AST、原始 Map、文件列表或路径查询；
- 不设置文件数量、单文件大小和目录总大小配置项；
- 不支持 TOML、JSONC、JSON5、YAML 多文档和跨文件 Anchor；
- 不支持 `.env`、`${NAME:-default}`、命令替换、配置覆盖层或 `include`；
- 不启动 goroutine，不保存包级可变状态，不依赖日志或 BufferPool；
- 库代码只返回错误，不控制进程退出。

## 7. 验收记录

完成日期：2026-07-26。

### 7.1 实际实现

- 新增公开 `config` 包，公开面保持为 `LoadDir`、`Duration`、`ByteSize` 及必要的文本解码和读取方法；
- 目录扫描实现递归发现、大小写不敏感扩展名、相对路径稳定排序、大小写折叠冲突检查和符号链接边界；
- JSON 使用标准库执行严格语法验证，YAML 固定使用 `github.com/goccy/go-yaml v1.19.2`；
- 内部配置树保留文件、行、列，完成 Mapping 递归合并、Sequence 追加和跨文件冲突定位；
- `${NAME}` 只在解析后的字符串 Scalar 中展开，支持 `$${NAME}` 转义，类型转换错误不包含环境变量值；
- 强类型解码支持零 Tag `snake_case`、可选 `json` Tag、匿名嵌入、Map、Slice、Array、Pointer、基础类型和 `encoding.TextUnmarshaler`；
- 未知结构体字段、字段映射冲突和递归匿名嵌入均返回 `CodeInvalidConfig`；
- 解码在临时目标中完成，失败不会修改调用方原对象；已有默认 Pointer 和 Map 在需要更新时先复制，避免间接污染；
- 新增静态 `testdata`、单元测试、并发测试、Fuzz 和 Benchmark，没有增加辅助 `main` 或后台 goroutine。
