# Origin 第三版 M8 Node 时间轮内核实施计划

> 文档状态：已完成
> 创建日期：2026-07-27
> 对应设计：[M8 Node 时间轮内核设计](../design/milestones/M8-节点时间轮内核设计.md)

## 1. 实施目标

M8 建立每个 Node 独立拥有的最终 Deadline 时间基础设施，供 M9 Await、后续 RPC、业务
Timer、心跳和重连直接复用。本里程碑不执行用户回调，也不实现 Service Scheduler。

实现必须满足：

- 基础 Tick 固定为 `10ms`；
- 五层、每层 `256` 槽的分层时间轮；
- 每个 Engine 一个可复用 `time.Timer` 和一个可等待退出的工作 goroutine；
- 空闲时不固定轮询；
- 登记和已知 ID 取消平均 `O(1)`；
- 到期只向所属 `DeadlineQueue` 交付 `DeadlineID`；
- `timerEntry` 使用 Engine 私有 `sync.Pool`；
- Node 在全部 Service `OnInit` 成功后启动 Engine，在全部 `OnStop` 完成后关闭 Engine。

## 2. 代码范围

新增内部包：

```text
internal/timerwheel
```

计划文件：

- `options.go`：时钟、可复用唤醒源和构造选项；
- `engine.go`：Engine 生命周期、工作循环、Deadline API 和统计；
- `wheel.go`：五层时间轮、位图、桶、级联和大步推进；
- `queue.go`：DeadlineQueue、到期环形队列和合并通知；
- `entry.go`：侵入式条目、唯一 ID、对象池和引用清理；
- `error.go`：内部关闭哨兵和稳定错误码映射；
- 对应 `*_test.go`、`benchmark_test.go`。

修改：

- `node/node.go`：创建、启动和关闭当前 Node 的 Engine；
- `node/node_test.go`：验证 Engine 与 Service 生命周期的先后顺序和失败回滚。

## 3. 实施步骤

### 3.1 Engine 基础类型

1. 建立 Created、Running、Closed 一次性状态机；
2. 构造时校验 Clock 和 WakeSource；
3. Start 记录单调基准时间并创建唯一工作 goroutine；
4. Close 拒绝新工作、清理全部 Queue、停止唤醒源并等待 goroutine；
5. 重复 Close 保持幂等，重复 Start 返回明确参数错误。

### 3.2 五层时间轮

1. 使用 `5 × 256` 固定桶和每层四个 `uint64` 非空位图；
2. `timerEntry` 同时加入时间轮桶和所属 Queue 的 Scheduled 链表；
3. 根据 `deadlineTick-currentTick` 定位最低可容纳层；
4. 通过位图寻找下一次到期或级联边界，不逐个扫描空 Tick；
5. 大步推进时依次处理真正非空的级联点和 L0 到期桶；
6. 同 Queue、同 Tick 保持登记顺序。

### 3.3 DeadlineQueue

1. Queue 由 Engine 创建并登记；
2. ScheduleAfter 使用绝对单调 Deadline 向上取整到 10ms；
3. Cancel 通过全局 ID 索引和侵入式链表完成平均 O(1) 删除；
4. 到期 ID 进入 Queue 私有环形队列，并使用容量 1 Channel 合并通知；
5. DrainExpired 复用调用方 Slice，分批取出并维持剩余通知；
6. Queue Close 批量清理未到期和已到期 ID，不扫描其他 Queue。

### 3.4 对象池和统计

1. Engine 私有 `sync.Pool` 复用 `timerEntry`；
2. 回池前清空 Engine、Queue、链表和 Deadline 引用；
3. ID 在 Engine 生命周期内单调递增且永不复用；
4. 统计 Scheduled、Expired、Queue、峰值、总登记/取消/到期/清理、唤醒、级联、
   分层条目、延迟和停止耗时；
5. 测试模式可选记录条目新分配、复用和回收次数。

### 3.5 Node 生命周期接入

1. Node 构造时创建独立但尚未启动的 Engine；
2. 所有 `OnInit` 成功后启动 Engine；
3. `OnStart` 失败回滚时先反序 `OnStop`，再关闭 Engine；
4. 正常停止时先反序 `OnStop`，再关闭 Engine；
5. `OnInit` 失败时 Engine 不启动，回滚只关闭未启动实例；
6. TimerEngine 错误与 Service 停止错误使用 `errors.Join` 保留。

## 4. 测试与性能验证

单元测试至少覆盖：

- 10ms 边界、零延迟、向上取整和不提前触发；
- 五层定位、每层边界、回绕、级联和大步推进；
- 同 Tick 顺序、跨 Queue 隔离、合并通知和分批 Drain；
- Cancel/Expire/Queue Close/Engine Close 竞争；
- 非法参数、重复 Start/Close、ID 归属和溢出；
- 条目完整清零、池化统计和引用释放；
- Node 正常启动、OnInit 失败、OnStart 失败和 Stop 错误路径；
- goroutine 退出和多 Engine 隔离。

Benchmark 至少覆盖登记、取消、到期、级联、并发登记/取消、多 Queue、10ms 精度和
`10,000`、`100,000`、`1,000,000` 活跃 Deadline 容量。
