# 12：故障排查

## 排查顺序

1. 先看启动错误和稳定错误码。
2. 再读取 `Application.Diagnostics()` 或诊断 HTTP 快照。
3. 对 RPC 检查目标 Service、Node、发现状态、Transport 和超时。
4. 对服务发现检查 Provider 连接、TTL、网络、TLS/认证和关注规则。
5. 必要时短时开启 pprof；完成后关闭。

超时应按稳定错误码进入业务降级或重试分支：

```go
if errs.CodeOf(err) == errs.CodeDeadlineExceeded {
    // 只对稳定超时错误执行有限降级、重试或返回可识别的业务错误。
}
```

## 控制命令 timeout，但 Application 仍在运行

`retire`、`resume` 和 `stop` 的 `--timeout` 只限制当前外部命令的总等待时间。退出码 `4` 不表示目标已被终止，也不证明批量状态操作完全没有发生。

按以下顺序排查：

1. 检查目标进程和 `<app>.pid` 锁是否仍存活；不要因为命令 timeout 直接删除 PID 或控制文件。
2. 查看目标日志中 Retire/Resume 的 Node、Service 聚合错误和 Provider 发布错误。
3. 读取 Diagnostics，逐个确认 Service 当前是 Running、Retired、Stopping 还是 Failed。
4. 检查 discovery Provider 是否 Recovering，以及远端快照是否尚未收敛。
5. 批量操作可能部分提交且不会事务回滚；确认实际状态后再幂等重试 `retire`/`resume`，或进入明确的 Stop/告警流程。

timeout 不会强杀进程；Stop 的内部优雅关闭期限与外部命令等待上限也是两个独立边界。
