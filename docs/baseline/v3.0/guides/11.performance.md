# 11：性能测试与容量理解

## 我想自己运行 RPC 基准测试

运行：[examples/11-performance/01-local-rpc-benchmark](../../../../examples/11-performance/01-local-rpc-benchmark)、[TCP](../../../../examples/11-performance/02-tcp-rpc-benchmark) 或 [NATS](../../../../examples/11-performance/03-nats-rpc-benchmark)。每个目录的 `run` 脚本会打印实际执行的 `go test -bench` 命令。

```bash
# 只运行指定 Benchmark，跳过普通测试；benchmem 输出分配指标。
go test ./tests/integration/rpcfixture -run '^$' \
  -bench '^BenchmarkGeneratedRemoteLoopback$' -benchmem -benchtime=3s
```

## 我该看什么指标

- QPS：每秒完成的请求数。
- TPS：每秒完成的业务事务数；一个事务可以包含多个 RPC。
- 延迟：单次完成时间，应同时观察平均值和分位数。
- 吞吐：单位时间传输的字节量；大 Payload 时比单纯 QPS 更有意义。

先固定 Go 版本、机器、并发、Payload、Transport 和依赖版本，再比较结果。不要把某次机器上的 TCP/NATS 结果外推为所有部署环境的绝对结论。

基线结论见：[RPC 性能测试结论](../design/details/2026-08-02-RPC性能测试结论.md)。
