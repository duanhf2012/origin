# Origin 第三版 M1 日志库实施计划

> 计划状态：已完成
> 创建日期：2026-07-25
> 对应里程碑：[M1 日志库里程碑设计](../design/milestones/M1-日志库里程碑设计.md)

## 1. 实施目标

在 M0 基础之上完成可独立创建、使用、刷新和关闭的日志库。只实现 M1 已确认范围，不接入 Application、Node、Service，也不提前实现 M2 对象池。

## 2. 实施步骤

1. 扩展 `errs`：
   - 增加 `CodeLogClosed=7001` 和 `CodeLogOutputFailed=7002`；
   - 增加固定错误、标准文本和单元测试。
2. 实现公共 `log` 核心：
   - Level、Mode、Format、Config 和 `DefaultConfig()`；
   - 类型化 Field、Any 不可变快照、Record、Caller 和 Handler；
   - 具体 Logger、`With`、`WithCallerSkip`、`NewNop()`；
   - 单日志协程 Runtime、固定 10000 事件队列、异步与同步模式；
   - Stats、队列满丢弃、ErrorStack 可靠写出、Flush 和幂等 Close。
3. 实现 `log/internal/rotate`：
   - 稳定活动文件；
   - 大小和 Local/UTC 自然日滚动；
   - 归档名冲突处理；
   - 保留期限、数量、gzip 压缩和临时文件恢复；
   - 唯一归档维护协程及完整关闭。
4. 实现 `log/zaplog`：
   - 固定依赖 `go.uber.org/zap v1.28.0`；
   - 独立控制台与文件 Level、JSON/Text Encoder；
   - stdout/stderr 互斥；
   - Origin Field 到 Zap Field 的类型化转换；
   - 实例级自定义 Encoder Option，不使用全局注册。
5. 实现进程级 Crash 输出：
   - 显式 `InstallCrashOutput`；
   - 派生 crash 文件路径；
   - 安装前滚动和维护旧 Crash 归档；
   - 幂等取消注册，不由 Runtime 或 Handler 隐式安装。
6. 补充测试和示例：
   - 包内单元测试覆盖配置、Field、Caller、模式、队列、Flush、Close 和错误路径；
   - 文件滚动、跨日、保留、压缩与 Crash 使用确定性测试；
   - `tests/integration/logging` 覆盖公共 Logger 与 Zap Handler 组合；
   - `_test.go` Go Example 展示默认和自定义 Handler 用法；
   - 保存关闭级别、异步、字段、Caller、同步、堆栈、满队列、编码和滚动 Benchmark。
7. 完成质量门禁并记录结果。

## 3. 关键实现边界

- `log` 不导入任何 Zap 包，`log/zaplog` 单向依赖 `log`。
- 普通异步日志的编码和 I/O 只在日志协程执行。
- Logger 方法不返回 error；生命周期和构造失败使用统一错误码。
- 不为每条日志创建 goroutine，不提前引入对象池或 unsafe。
- Runtime、Handler、文件、日志协程和归档协程均有唯一所有者。
- Crash 输出是显式进程级能力，同一进程只允许最终入口持有一个实例。
- 配置文件解析、全局 Logger、热更新、远程日志、Trace 和 Application 接入不进入 M1。

## 5. 验收记录

验收日期：2026-07-25。

已完成：

1. `errs` 已增加稳定日志错误码 `CodeLogClosed=7001` 和 `CodeLogOutputFailed=7002`，并提供固定错误与测试。
2. `log` 已实现配置、类型化 Field、不可变 Any/Bytes 快照、Caller、Stack、Logger、Handler、Runtime、Stats、Flush、Close 和 Nop Logger。
3. 每个 Runtime 只创建一个日志协程；固定 10000 槽位在采集 caller 和复制事件前预占，满队列路径不阻塞且不分配。
4. 异步、同步和 `ErrorStack` 可靠写出均已实现；关闭会停止准入、等待正在提交的调用、排空事件，再执行 Handler Sync 和 Close。
5. `log/internal/rotate` 已实现大小与 Local/UTC 自然日滚动、同毫秒冲突处理、期限与数量保留、gzip 原子压缩、临时文件恢复和唯一归档维护协程。
6. `log/zaplog` 已固定使用 Zap v1.28.0，完成 console/file 独立级别、JSON/Text、自定义实例级 Encoder、stdout/stderr 互斥以及文件输出。
7. `InstallCrashOutput` 已实现显式进程级注册、旧 Crash 文件启动前滚动和幂等取消；子进程测试验证未捕获 panic 同时保留在 stderr 和 Crash 文件。
8. 跨包集成测试位于 `tests/integration/logging`，简单使用示例位于 `log/example_test.go`，没有建立额外测试程序或空示例目录。
9. 实现中通过 Benchmark 发现提交计数若为每次日志创建等待 channel，会让满队列路径产生一次堆分配；最终改为 Runtime 自有 `sync.Cond`，不引入对象池，满队列路径达到零分配。
