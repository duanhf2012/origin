# Origin 第三版 M16 完整停止、异常恢复与进程集成实施计划

> 当前状态：已完成
>
> 创建日期：2026-07-29
>
> 对应设计：[M16 完整停止、异常恢复与进程集成设计](../design/milestones/M16-完整停止异常恢复与进程集成设计.md)

## 1. 目标

在不实现 Origin/etcd Discovery Provider、Module、退休控制和事件系统的前提下，把 M7～M15
已经建立的启动、调度、Timer、RPC、发现目录和命令行能力接成一条可验证的完整生命周期：

1. 所有 Service 纯 `OnInit` 均执行并按配置顺序聚合错误；
2. 正常停止按 `Draining -> Finalizing -> Stopped` 排空，`OnStop` 可以顺序使用 Await；
3. 单任务和业务 Worker panic 被隔离并记录完整堆栈；
4. 真正不可恢复的单 Service Scheduler 故障被隔离，不停止 Application；
5. TCP Listener 与 NATS Connection 在运行期持续恢复，不再取消 Application；
6. Node 提供无锁 `TransportStatus`、`HealthStatus` 和冷路径 `ServiceStatus`；
7. Application 使用唯一总体停止 Context，并按顺序完成 BufferPool、Crash 和日志收尾；
8. Windows、Linux、真实 TCP/NATS、Race 和进程信号均通过验收。

## 2. 实施边界

- 不实现 Origin 内置服务发现、etcd Lease/Watch、Provider 配置或网络协议；
- 不实现 Service Retire/Resume；只保证未来 Retired 状态不被健康逻辑当作故障；
- 不实现 Module、同步/异步事件、复杂路由、Broadcast 多 Node、gRPC 或 TcpModule；
- 不增加 TaskScope、父子任务树、WorkerManager、第二份任务计数或第二套 Scheduler；
- 不为恢复次数、退避、健康状态和日志窗口增加业务配置；
- 不改变生成 RPC 契约和客户端外观；
- NATS 恢复只更换内部 Transport generation，Node `SessionID` 在进程内保持不变；
- 热路径不增加反射、字符串状态、锁、每 RPC Timer 或每调用堆分配。

## 4. 验收底线

M16 只有在以下条件同时成立时才算完成：

- Service 停止过程中没有新业务任务进入，已接受任务和 Await 全部完成后才执行 `OnStop`；
- `OnStop` 可以使用顺序 Await 保存数据，返回前不会与普通任务并发；
- 单 Task panic 不终止 Service，Scheduler 真正损坏只隔离单 Service；
- TCP/NATS 故障不会自动停止 Application，恢复后不重复生命周期或旧请求；
- 状态查询不进入 RPC 热路径锁，Benchmark 证明无查询分配；
- StopTimeout 是整次清理唯一预算，不在日志或 Node 阶段重新计时；
- Windows、Linux、真实 NATS、Race 和进程信号测试全部通过；
- 文档、代码、测试和提交处于同一可复现检查点。
