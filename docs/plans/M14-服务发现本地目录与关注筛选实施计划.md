# Origin 第三版 M14 服务发现本地目录与关注筛选实施计划

> 文档状态：已完成
>
> 创建日期：2026-07-29
>
> 对应设计：[M14 服务发现本地目录与关注筛选设计](../design/milestones/M14-服务发现本地目录与关注筛选设计.md)

## 1. 目标

在不引入 Origin、etcd 或 NATS Discovery Provider 的前提下，完成每个 Node 独立拥有的
服务发现目录，并把已经实现的 TCP RPC 从 Application 直接装配目标，收敛到统一的发现
事实：

1. 增加公开 `discovery` 只读类型、Service 查询、等待和监听外观；
2. 增加 `internal/discovery` 完整原始快照、关注筛选、不可变索引、Diff 和原子发布；
3. 使用 Application 内部过渡数据源模拟独立部署时的完整发现流程；
4. 增加 Node 级统一就绪发布屏障，全部 Service 完成 `OnStart` 后才整体公开；
5. 允许 `OnStart` 使用现有 `Service.Await`、生成 RPC Await 和发现等待；
6. 让 TCP 目标、SessionID 握手、路由准入和断线清理全部由发现目录驱动；
7. 把发现监听回调送入所属 Service 的唯一 FIFO Runner，并支持 Await、合并和取消；
8. 通过单元、真实 TCP、竞态、Fuzz、Benchmark、覆盖率和跨平台验证完成里程碑。

## 2. 实施边界

- 不实现 Origin、etcd、NATS Discovery Provider，也不增加 `static` Provider；
- 不实现 NATS RPC、自动路由、Broadcast、热更新关注规则、服务退休控制接口或完整优雅
  停服状态机；
- 不增加服务发现数量上限、监听器数量配置、业务公开目录统计或可写目录对象；
- 不改变生成 RPC 客户端外观，不为 OnStart 生成另一组调用方法；
- 不按 Service 建立 TCP 连接；同一远端 Node 的多个 RPC Service 共享一条目标连接；
- 不把同一 Application 内的 RPC 短路为 Go 指针调用，集成测试仍使用真实 TCP；
- 不在 RPC 热路径复制公开 DTO、标签或候选列表；
- 不为不可变快照、公开事件或 Task 新增未经 Benchmark 证明必要的对象池；
- 新增和修改代码遵守 `AGENTS.md`，具有完整中文 GoDoc、步骤注释、并发所有权和回滚
  说明。

## 3. 包与文件职责

### 3.1 公开 `discovery`

新增：

- `discovery/types.go`：`State`、`Instance`、事件 Service、`Event` 和 Transport 无关的
  公开只读 DTO；
- `discovery/listener.go`：`IListener`、`ListenerID` 及 ID 零值语义。

公开包不保存目录指针，不公开地址、Transport、ContractID 或 ContractFingerprint。

### 3.2 内部 `internal/discovery`

新增：

- `raw.go`：`RawSnapshot`、`RawNode`、`RawService`、内部 Transport 和 ServiceState；
- `filter.go`：启动期编译的 `allow_discovery` 规则和精确匹配；
- `snapshot.go`：不可变 Instance、精确索引、按 Service 索引和连接目标索引；
- `directory.go`：完整校验、规范化、Diff、版本推进和 `atomic.Pointer` 发布；
- `source.go`：Application 过渡数据源、完整快照广播、订阅关闭和公开 Node 记录管理。

`internal/discovery` 只实现发现数据算法与所有权，不调用 Service 业务回调，也不持有 TCP
连接。写入由 Node 冷路径串行化，读取不加锁。

### 3.3 `service`

修改：

- `service/runtime.go`：增加由所属 Node 实现的窄发现桥接接口；
- `service/service.go`：组合公开查询、等待、监听注册和监听取消方法；
- `service/await.go`：识别普通 Task Context 与当前 OnStart 生命周期 Context；
- `service/scheduler.go`：Prepared 阶段启动 Deadline watcher；增加最多一个待执行的发现
  同步任务，队列满时保留待提升标记；
- 新增 `service/start_context.go`：只供框架 Node 创建、失效和验证 OnStart 私有令牌；
- 新增 `service/discovery_task.go`：框架内部发现脏标记与 FIFO 任务提升入口。

普通业务 Runner 仍只在整个 Node 越过就绪屏障后启动。OnStart Await 在原生命周期
goroutine 中直接执行等待函数，不创建替补 Runner 或辅助 goroutine。

### 3.4 `node`

修改或新增：

- `node/config.go`：增加 Node 标签和预编译关注规则；
- `node/node.go`：创建独立目录、SessionID、发现订阅和统一就绪发布屏障；
- `node/runtime.go` 或现有 Runtime 文件：实现 Service 的公开发现桥；
- `node/discovery_runtime.go`：串行 Apply、监听器状态、等待者、事件净变化和 TCP 目标
  对账触发；
- `node/discovery_listener.go`：监听注册、移除、首次补发、独立事件复制和 panic 隔离；
- `node/discovery_wait.go`：无轮询的 `AwaitService`、`AwaitNodeService` 等待；
- `node/discovery_publish.go`：构造当前 Node 的公开 RawNode、整体发布与撤销。

Node Stop 或启动回滚必须关闭等待者、移除监听器、撤销发布、取消连接对账并关闭目录订阅。

### 3.5 `rpc`

修改：

- `rpc/runtime.go`：增加由 Node 实现的远端发现解析接口和入站就绪门；
- `rpc/remote_runtime.go`：增加只保留最新目标集合的非阻塞连接对账入口；
- `rpc/remote_target.go`、`rpc/remote_session.go`：目标和连接绑定 SessionID；
- `rpc/inbound_handler.go`、`rpc/wire.go`：Hello/Ack 增加双方 SessionID 校验；
- `rpc/dispatcher.go` 或相邻文件：向 Node 提供稳定公开 Service 契约目录。

远端请求提交顺序固定为：读取发现快照、校验可见实例与契约、取得与 SessionID 一致的
当前连接、发送。找不到发现实例返回 `CodeRPCNoRoute`；已经发现但连接尚未就绪返回
`CodeTransportUnavailable`。

### 3.6 `application`

修改：

- `application/config.go`：严格解析 `labels` 与可省略、空列表、非法 null 可区分的
  `allow_discovery`；
- `application/application.go`：创建唯一过渡数据源，把同一实例交给本次实际启动的全部
  Node，删除 M13 直接互相 `AddTarget` 的装配；
- 启动和失败回滚保持配置顺序，停止保持真实启动顺序的严格反序。

过渡数据源只保存公开 RawNode 记录，不拥有任何 Node 的可见快照。

## 4. 核心实现外观

### 4.1 公开发现类型

```go
package discovery

type State uint8

const (
    StateUnknown State = iota
    StateRunning
    StateRetired
)

type Instance struct {
    NodeID      string
    SessionID   string
    ServiceName string
    State       State
    Labels      map[string]string
}

type Service struct {
    ServiceName string
    State       State
}

type Event struct {
    NodeID   string
    Services []Service
}

type ListenerID uint64

type IListener interface {
    OnDiscovered(context.Context, Event)
    OnStateChanged(context.Context, Event)
    OnLost(context.Context, Event)
}
```

### 4.2 Service 外观

```go
func (s *Service) FindDiscoveredService(
    nodeID string,
    serviceName string,
) (discovery.Instance, bool)

func (s *Service) ListDiscoveredServices(
    serviceName string,
) []discovery.Instance

func (s *Service) AwaitService(
    ctx context.Context,
    serviceName string,
) error

func (s *Service) AwaitNodeService(
    ctx context.Context,
    nodeID string,
    serviceName string,
) error

func (s *Service) AddDiscoveryListener(
    listener discovery.IListener,
) (discovery.ListenerID, error)

func (s *Service) RemoveDiscoveryListener(
    id *discovery.ListenerID,
) bool
```

查询返回业务独立副本；等待只等待远端可见实例，Running、Retired 和零 RPC 契约均可
满足；指向当前 Node 的 `AwaitNodeService` 立即返回参数错误。

### 4.3 RPC 内部发现解析

RPC 包定义最小使用方接口，Node 适配器实现它，避免 RPC 依赖发现目录具体类型：

```go
type RemoteResolver interface {
    ResolveRemote(
        nodeID string,
        serviceName string,
        contractID ContractID,
        fingerprint ContractFingerprint,
    ) (RemoteRoute, error)
}

type RemoteRoute struct {
    NodeID    string
    SessionID string
    Address   string
}
```

该接口只在远端 RPC 提交热路径调用。实现直接读取不可变索引，不构造 Map Key 字符串、不
复制标签、不返回 Slice，以 `0 allocs/op` 为验收目标。

### 4.4 OnStart 生命周期令牌

Node 在调用单个 `OnStart` 前通过 service 框架装配函数取得私有 Context 和失效函数：

```go
startCtx, finish, err := service.PrepareStartContext(entry.instance, parent)
if err != nil {
    return err
}
defer finish()
err = entry.instance.OnStart(startCtx)
```

令牌固定所属 Scheduler、Service 和启动代次。`finish` 后旧 Context 不能再次 Await。
该函数是跨 `node`/`service` 的框架装配入口，不成为业务推荐 API。

Prepared Scheduler 创建后立即启动只负责 Context 到期取消的 Deadline watcher；
`ActivateScheduler` 只启动普通业务 Runner。Prepared 状态停止时也必须关闭并等待 watcher。

### 4.5 发现任务合并

每个 ServiceScheduler 只保存一组常数大小状态：

- `discoveryDirty`：目录存在尚未同步到监听器的状态；
- `discoveryQueued`：Ready 队列中已经存在发现同步 Task；
- `discoveryRunning`：当前发现同步 Task 正在执行；
- `discoveryRun`：Node 注册的一份稳定交付函数。

目录更新只标脏：

1. 未排队、未运行且任务额度可用时，在同一 FIFO 尾部增加一个发现 Task；
2. Ready 满时保留脏标记，不返回目录更新失败；
3. 任一普通、Timer 或发现 Task 完成释放额度时尝试提升一次；
4. 发现 Task 开始前清除本轮脏标记；执行期间出现新版本会重新置脏；
5. Task 完成后若仍脏，再按 FIFO 和容量规则排队一次。

该状态直接属于 ServiceScheduler，不另建 Channel 或第二个工作队列。

## 6. 实现不变量

1. 每个 Node 只拥有一份当前可见目录；Application 只拥有原始过渡数据源。
2. 目录写入可以加冷路径短锁，RPC 精确查询不得取得该锁。
3. 无效完整快照整批拒绝，不能发布部分合法实例。
4. 公开查询和事件归业务独立持有，内部 RPC 查询不使用复制接口。
5. 同一逻辑实例 SessionID 改变必须先 Lost 旧会话，再 Discovered 新会话。
6. 发现状态先发布，TCP 目标随后异步对账；连接失败不回滚发现事实。
7. 未发现目标不建立 TCP 连接，也不能绕过目录使用历史连接。
8. 全部 OnStart 成功前，当前 Node 的任一 Service 都不能被远端发现。
9. OnStart Await 不启动普通 Runner，不允许其他业务任务并发访问当前 Service。
10. 监听回调只由所属 Service FIFO Runner 执行，Provider 和网络 goroutine 不执行用户代码。
11. 队列满只合并发现同步意图，最终状态不能丢失，关键 RPC/Timer 任务不能静默丢弃。
12. Stop、回滚和重复关闭都必须收回 Source 订阅、等待者、监听器、连接和 goroutine。
