> 对应设计：[M21 业务运行时扩展收口设计](../design/milestones/M21-业务运行时扩展收口设计.md)

**Goal:** 用四个可独立回滚的工作包完成冻结配置视图、Module 生命周期、本地事件和 Retire/Resume，形成 Origin 第三版最后一个业务运行时能力里程碑。

**Architecture:** `config.Snapshot/View` 保存一次加载后的不可变配置树；Application、Node、Service 只传递廉价视图。Module 归属于一个 Service，共享该 Service 的调度器并由统一生命周期协调器管理。事件总线按 Service 隔离，同步通知复用当前 Task，异步通知只占一个 M9 Ready 项。Retire/Resume 先提交本地状态，再由每个 Node 唯一的发布协调器合并服务发现快照并等待发布代次确认。

**Tech Stack:** Go 1.26.5、Origin M3 配置树、M7 生命周期、M8 Timer、M9 Service Scheduler、M17/M18 Discovery Provider。

## 全局约束

- 严格按配置、Module、事件、Retire/Resume 四个工作包实施并分别提交；后一个工作包只依赖前一个已通过测试的公开边界。
- 每个行为先写失败测试并确认失败原因，再写最小实现；禁止用只验证 mock 调用次数的测试替代行为测试。
- 新增集合均惰性分配：每个 Service 最多 4096 个 Module、深度最多 64、最多 4096 个事件 ID 和 65536 个监听器。
- 用户回调必须逐个恢复 panic、聚合错误并继续清理；热路径不得为每个 Module、监听器或发现发布创建 goroutine。
- Service 与 Module 的业务 API 只能在所属 Service 调度语义内执行；同步事件禁止 `Await`，嵌套同步事件深度最多 64。
- Retire/Resume 的本地状态转换不因发现发布失败回滚；Stop 优先于并发的 Retire/Resume。
- 所有新增公开符号写中文 GoDoc；并发、所有权、资源上限和失败语义写在实现附近。

**Lifecycle:**

```text
OnInit:  Service -> 注册点同步深度优先 Module
OnStart: Module 父先子后深度优先 -> Service
OnStop:  Service（仅 OnStart 已进入）-> Module 严格逆序
```

Module 直接委托 `Timer/Await/DispatchAsync/GoSafe/RunSafe/Config`，同时记录 Timer、事件订阅等长期资源的所属 scope。Module 启动失败时 Service.OnStart 不进入，所有已启动 Module 在 Node 回滚的独立 stop context 中逆序停止；Service.OnStart 失败时 Service.OnStop 仍先执行，再逆序停止 Module。所有错误和 panic 聚合，不中断后续清理。

**Public API:**

```go
func (s *Service) Retire(context.Context) error
func (s *Service) Resume(context.Context) error

const ServiceStateChangedEventID EventID = EventID(^uint32(0))
type ServiceStateChanged struct {
    Previous State
    Current  State
    ChangedAt time.Time
}
```

Running -> Retired 和 Retired -> Running 为唯一有效转换；同状态幂等。外部调用投递一个控制 Task 并等待，所属 Task 内调用直接执行且发布等待通过 `Await` 释放执行槽。状态转换先原子提交 entered-time，再异步提交内建事件，最后等待 Node 发布代次；事件或发布失败不回滚本地状态。Retired 继续允许 Timer、Await、DispatchAsync、GoSafe/RunSafe 和精确 RPC，默认自动选择仍排除 Retired。

每个 Node 只启动一个有界发布协调器。状态变化递增 desired generation 并以容量一唤醒信号合并；发布者每轮重新构造完整快照，成功后推进 acknowledged generation 并广播等待者。等待目标代次的调用可由当前或更新代次的成功 ACK 满足；失败唤醒对应等待者并保留 Provider 的 expected snapshot，后续恢复沿用 M17/M18 重试。停止发布者后先阻止新状态转换，再撤销发现注册。

Node 的 `Retire/Resume` 依次处理 Service；Application 的 `Retire` 按 Node 启动逆序、每个 Node 内 Service 启动逆序，`Resume` 按正序。批量操作 best-effort 聚合所有错误，不引入 Node/Application 的 Retired 状态。
