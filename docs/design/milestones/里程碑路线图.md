# Origin 第三版里程碑路线图

> 文档状态：已确认  
> 确认日期：2026-07-25  
> 最后更新：2026-07-26

## 1. 目标

Origin v3 不再用一个大里程碑同时实现基础库、运行时、调度器、代码生成、RPC 和优雅停止。

新的里程碑遵循：

1. 每个里程碑只交付一个边界清晰、可以独立测试的结果；
2. 前置基础库不依赖 Application、Node、Service 或 RPC；
3. TCP 与 NATS 基础库只处理连接、字节和资源生命周期，不提前包含 RPC 方法、ServiceName、ContractID 等语义；
4. 后续里程碑只能依赖已经验收的前置里程碑；
5. 已经讨论完成的详细设计继续作为设计储备，进入对应里程碑时再裁剪实现范围；
6. 每个里程碑完成后保存测试、Benchmark、分配和竞态检测基线。

每个里程碑对应的必读设计、缺失设计和 Review 门禁见[里程碑设计文档复核清单](./里程碑设计文档复核清单.md)。

## 2. 前置独立库阶段

### M0：工程基础

- Go module、目录和包边界；
- 最低 Go 版本和基础依赖规则；
- 轻量错误类型与基础错误码；
- BuildTime、版本和提交信息注入；
- 单元测试、Benchmark、竞态检测和生成代码校验入口。

M0 不依赖 Zap、Protobuf、NATS 或 Application。

### M1：日志库

- Zap 类型化日志门面；
- 控制台和文件独立级别；
- 异步日志协程与开发同步等待模式；
- 文件行号、`ErrorStack`、滚动、保留、压缩和 crash 文件；
- 可替换 Handler 和自定义 Encoder。

### M2：内存复用库

- 内部 Buffer、容量档位和单一所有权；
- Reset、重复释放检查和大 Buffer 回收边界；
- 逃逸分析、分配 Benchmark 和突发流量后的内存滞留测试。

M2 不实现 `pendingCall`、TimerEntry 或 Protobuf 消息池，这些对象进入其所属运行时里程碑。

### M3：基础配置库

- 配置目录递归扫描；
- YAML、JSON 文件读取；
- 确定性文件顺序；
- 重复定义、非法格式和来源位置错误；
- 配置片段解析到强类型结构体。

M3 不提前定义完整 Application、Node、Service 业务配置模型。

### M4：程序命令与进程控制

- Command Runner；
- `start`、`stop`、`help`、`version` 和自定义离线命令；
- 必填 `--app-name`、PID 文件锁、Unix 信号和 Windows 普通控制台停止请求文件；
- BuildTime 在 help 中的条件显示；
- 通过可注入的生命周期 Handler 和测试进程验证，不依赖真实 Application。

详细范围和开工待确认项见
[M4 程序命令与进程控制库设计](./M4-程序命令与进程控制库设计.md)。

实际 Application 的启动和优雅停止接入放在 M12。

### M5：TCP 网络基础库

- Listener、Connection 和连接关闭；
- 长度帧、最大包限制、完整写入和短写处理；
- 有界发送队列和过载返回；
- 与 M2 Buffer 的所有权转移；
- 网络 goroutine 的创建、退出和泄漏检查。

M5 不包含 RPC RequestID、ContractID、MethodID、ServiceName、错误映射和路由。

### M6：NATS 基础库

- NATS 连接、发布、订阅和请求—响应基础封装；
- Context、超时、重连通知和关闭；
- 连接及订阅资源回收；
- 面向真实 NATS 的集成测试。

M6 不生成 RPC 方法，也不强迫 NATS 与 TCP 暴露完全相同的基础接口。二者在后续 RPC Transport 适配层统一。

## 3. 框架核心阶段

### M7：Application、Node 与 Service 最小生命周期

- Application 管理并选择启动一个或多个 Node；
- Service 工厂注册、实例创建和 Node 归属；
- Node 与 Service 基本状态机；
- 最小配置模型和显式启停顺序；
- 不使用包级全局 Service 实例或 Node 单例。

### M8：Service 调度、Await 与内部 Deadline

- FIFO Ready 队列和单执行槽；
- 普通任务 Runner 复用；
- Await 挂起、替代 Runner 和恢复交接；
- 内部 Deadline、默认 15 秒、取消与过载上限；
- 暂不接入远程 RPC。

### M9：RPC 契约、代码生成与本地 Dispatcher

- Go 接口契约扫描和生成命令；
- ContractID、MethodID 和稳定性规则；
- Protobuf 严格子集编解码；
- 强类型客户端、服务端 Dispatcher 和注册绑定；
- 不经过 TCP/NATS 的协议级单元测试。

### M10：TCP RPC 端到端闭环

- RPC 线协议；
- 静态 `NodeID + ServiceName` 目标；
- RequestID、pendingCall、超时和断线完成；
- M9 RPC Runtime 与 M5 TCP 的 Transport 适配；
- 单进程双 Node 和双进程单 Node 使用相同真实 TCP 路径。

### M11：NATS RPC 端到端闭环

- M9 RPC Runtime 与 M6 NATS 的 Transport 适配；
- 与 TCP 一致的调用、超时、取消和错误外观；
- 不在 NATS 适配器复制代码生成和业务 API。

### M12：完整停止、异常恢复与进程集成

- Stop 停止准入和既有任务排空；
- Waiting、pendingCall 和 Await 恢复清理；
- 独占 finalizer 与 `OnStop(ctx)` 中的 Await RPC；
- 用户代码 panic 隔离和框架 panic 受控停止；
- M4 start/stop、PID 控制、SIGINT、SIGTERM 与 Application 的统一接入；
- 日志最终排空、资源逆序释放和进程退出码。

## 4. 后续能力

M12 之后再按独立系统继续增加小里程碑，包括：

- Module 树；
- 业务 Timer、Ticker 和 Cron；
- 同步与异步本地事件；
- Service 业务配置；
- 内置服务发现、etcd、TTL、发现与失去发现事件；
- 服务关注筛选、标签、退休和恢复；
- RoundRobin、Rand、ModKey 和自定义路由；
- Async、Notify 和 Broadcast 完整语义；
- 普通 Go 类型、自定义结构体和混合 Protobuf 序列化；
- 外部 gRPC 插件；
- KCP、WebSocket、HTTP、数据库、Redis、MongoDB、Kafka 等适配器。

这些能力不再集中到一个“核心完备”里程碑，而是每个系统单独建立里程碑和实施计划。

## 5. 执行规则

1. 当前只为即将开工的里程碑编写可执行实施计划。
2. 后续里程碑只保留范围和依赖，不提前锁死内部实现。
3. 一个里程碑未通过验收，不同时开工依赖它的后续里程碑。
4. 发现前置设计不足时，先回到对应详细设计确认，不把临时决定埋进实现。
5. 原最小闭环文档仅作为 M7～M12 的拆分储备。
6. 开工前必须在[里程碑设计文档复核清单](./里程碑设计文档复核清单.md)中完成 Review 记录；仍有草案或待补设计时不得编写实现代码。
