## 1. 用途

本文列出 M0～M12 在实施前必须重新阅读和 Review 的设计文档。

每个里程碑开工前必须：

1. 阅读本里程碑设计；
2. 阅读本节列出的主设计文档；
3. 复核依赖里程碑的公开接口和验收结果；
4. 补齐“待补设计”；
5. 重新确认仍为草案或参数待定的内容；
6. 将 Review 日期、结论和调整记录写回本文；
7. 全部通过后，才为该里程碑编写实施计划和代码。

详细设计已经确认，不代表进入某个里程碑时不需要再次 Review。实现范围、依赖接口或性能数据发生变化时，应及时调整设计后再执行。

## 6. M2：内存复用库

### 主设计

- [M2 内存复用库里程碑设计](./M2-内存复用库里程碑设计.md)；
- [内存复用与对象池设计](../details/2026-07-25-内存复用与对象池设计.md)中的 Buffer 部分。

### 本里程碑不执行的同文内容

- `pendingCall` 到 M10/M11；
- `timerEntry` 到后续 TimerEngine；
- Application 持有 BufferPool 到 M7；
- TCP 所有权转移到 M5。

### 已确认

- `internal/bufferpool` 包路径、`bufferpool` 包名和内部可见性；
- `NewPool(Options)`、`Acquire`、`Bytes`、`Release` 和 `Stats` 外观；
- `Release` 定义在 Buffer 上以及重复释放的边界；
- `16 B`～`64 KiB` 固定档位和超大 Buffer 回收；
- 每档一个 `sync.Pool`，不使用有界 channel；
- 使用者通过启动配置决定是否统计，框架不区分开发与生产环境；
- 统计开关只在 Pool 创建时生效，不支持运行中动态切换；
- M7 将开关映射为 Application 级对外配置；
- 不公开 Config、Close、Append 或 Resize；
- 池化相对强制逃逸直接分配的 Benchmark；
- 开启与关闭统计的性能差异；
- 突发流量后的内存滞留验收方式。

### 主设计

- [M3 基础配置库里程碑设计](./M3-基础配置库里程碑设计.md)。

### 关联参考

- [Application 与 Node 生命周期设计](../details/2026-07-22-应用与节点生命周期设计.md)中的配置顺序和静态校验；
- [程序命令与进程控制设计](../details/2026-07-25-程序命令与进程控制设计.md)中的配置目录扫描；
- [Service 业务配置访问设计](../details/2026-07-24-服务业务配置访问设计.md)作为后续使用场景参考；
- [完整配置模型设计](../details/2026-07-26-完整配置模型设计.md)中的 v2 能力对照、多文件示例、统一时间/容量格式和顶层模型。

### 开工前必须确认

- 公开包和唯一的 `LoadDir(dir, dst)` 强类型加载外观，不公开 Loader 或 Snapshot；
- 目录扫描、大小写路径冲突与 Kubernetes 文件符号链接规则；
- 仅支持 JSON/YAML，以及 `github.com/goccy/go-yaml` 的版本和依赖边界；
- Node 与 Service 跨文件拆分、Mapping 递归合并、Sequence 追加、重复定义与禁止覆盖；
- 不提供 Options，不限制文件数量、单文件大小和总读取量；
- 错误来源文件、行列和通用错误码；
- 固定严格未知字段和默认值边界；
- `Duration` 与 `ByteSize` 的公开类型、严格语法和溢出规则；
- 普通字段零 Tag 自动转 `snake_case`，仅在改名或忽略时使用 `json` Tag；
- `${NAME}` 只在字符串 Scalar 中安全展开，缺失变量报错且不泄露变量值；
- M3 不读取 `.env`，不建立环境覆盖层，也不接入热更新或 Application 业务模型。
