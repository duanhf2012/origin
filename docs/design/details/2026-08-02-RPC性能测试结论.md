# Origin RPC 性能测试结论

> 文档状态：已完成 M22 权威性能验收
>
> 测试日期：2026-08-01（北京时间）
>
> 对应里程碑：M22 v3.0 发布前质量收口

## 1. 结论摘要

M22 已完成 Local、TCP、NATS 三种 Transport 下的 RPC 性能测试。测试覆盖 Async/Await、
32 B/1 KB/64 KB Payload、延迟和并发吞吐，共 24 个场景，每个场景执行 3 轮，共 72 个
原始结果。

最终结果：

- 72/72 结果成功；
- `errors`、`timeouts`、`pending_end` 总和均为 0；
- 测试过程没有 panic、fatal 或 etcd `too_many_pings` 告警；
- 全部场景均完成三轮，未删除或隐藏不利样本；
- 结果满足 M22 的性能与质量门禁，可作为 Origin v3 的首个 RPC 性能基线；
- 该基线用于同环境回归比较，不作为脱离 CPU、Go、内核、Transport 配置的绝对 SLA。

## 2. 测试口径

### 2.1 场景矩阵

| 维度 | 覆盖值 |
|---|---|
| Transport | Local、TCP、NATS |
| 调用方式 | Async、Await |
| 延迟场景 | 32 B，Concurrency 1 |
| 吞吐场景 | 32 B/Concurrency 64、1 KB/Concurrency 32、64 KB/Concurrency 32 |
| 每个场景 | 预热 5 秒，测量 15 秒，重复 3 轮 |
| 结果指标 | 完成 QPS、MiB/s、P50/P95/P99、错误、超时、B/op、allocs/op、pending_end |

完成 QPS 只统计业务语义真正完成的调用：

- Async 在最终 callback 返回后计数；
- Await 在响应校验、解码并返回后计数；
- 进入发送队列、写入 Socket 或收到 NATS Publish ACK 不计为完成。

## 4. 结果解读

### 4.1 Local

Local 路径没有网络跳转，32 B 单并发 Await 的 P50 为 4.221 us，是当前 RPC 调度、编码和
解码路径的低延迟参考。64 KB 场景仍保持较高吞吐，但 P95/P99 明显上升，说明大 Payload
下内存复制、编解码和调度成本成为主要因素。

### 4.2 TCP

TCP 结果体现了跨 Node 连接、Wire 分帧、Socket 收发和远端 Service 调度的固定成本。32 B
单并发 Await 的 P50 为 60.810 us；在 1 KB 和 64 KB 场景中，吞吐随 Payload 增长而受带宽、
编解码和缓冲区处理约束，尾延迟也随之增加。

### 4.3 NATS

NATS 结果包含客户端、NATS Server、集群路由和远端 RPC 的完整链路成本。32 B 单并发 Await
的 P50 为 156.764 us；64 KB 场景 P95 为 7323.052 us。NATS 适合复用现有消息集群和跨进程
解耦，不应直接用 Local 或 TCP 的绝对延迟目标衡量。

### 4.4 Async 与 Await

Async 和 Await 的完成口径不同，不能只比较 QPS 数字判断优劣。Async 反映回调投递完成，
Await 反映调用方解码返回完成；应在相同 Transport、Payload 和并发条件下，结合 P95/P99、
分配和业务协作方式选择。

## 6. 验收结论与后续使用

本报告结果可以作为以下用途：

1. 后续修改 RPC、编解码、调度、TCP/NATS Transport 时的同环境回归基线；
2. 评估 Payload 大小、并发度和 Transport 选择时的工程参考；
3. 对比统计埋点、连接恢复和队列策略调整前后的延迟与分配变化。

使用本报告时必须同时记录 Go 版本、CPU、逻辑核数、`GOMAXPROCS`、Transport 配置、etcd/NATS
版本和测试提交。不同机器、不同内核、TLS、认证、集群拓扑或消息配置下的结果不能直接与
本报告的绝对值比较，只能比较趋势和相对变化。

M22 性能门禁结论：通过。该结论表示发布候选质量收口完成，不表示已经建立面向所有业务
场景的统一性能 SLA。
