# 日志易用性、输出格式与运行时控制变更摘要

> 状态：已完成
> 基线：v3.0
> 目标版本：v3.1.0
> 兼容性：新增 API 与配置字段；v3.0 配置保持可加载，两个旧 Logger 方法仅废弃未删除
> 关联提交：本文件所在提交

## 使用外观

- 新增进程默认 `log.Default/SetDefault/Enabled` 和
  `log.Debug/Info/Warn/Error/ErrorStack`。包级函数只转发到 Application 已有 Runtime，
  不创建第二套 Handler、队列或 goroutine；调用者位置仍指向业务源码。
- 新增 `Module.Logger()`，直接委托所属 Service Logger；未绑定 Module 返回 Nop Logger。
- Service/Module Logger 自动带实际 `node_id`、`service_name`。`app_name`、`node_id`、
  `service_name` 作为保留 Key，业务字段不能伪造或覆盖。
- `Application.Logger()`、`Node.Logger()` 在 v3.1 保留源码兼容并标记 Deprecated；教程不再
  推荐，下一主版本才删除。

## 输出配置和格式

- Console/File 分别新增 `context_fields.node_id`、`service_name`，省略或空对象时默认都
  显示，显式 `false` 独立覆盖。
- text 改为 `TIME LEVEL [NODE/SERVICE] CALLER MESSAGE key=value`；本地时间不附带
  `+0800`，字符串、字段名、控制字符和复杂对象保持单行且无歧义。
- JSON 保持单行结构化对象，时间统一为 UTC RFC3339 毫秒 `Z`。
- 日志内容不再包含 `app_name`。Application 名仅作为活动、归档与 Crash 文件名前缀：
  `game + logs/origin.log -> logs/game-origin.log`。

## 运行时控制和诊断

- 新增 Console/File 对称接口：
  `SetConsoleLevel/ResetConsoleLevel`、`SetFileLevel/ResetFileLevel`、
  `SetConsoleEnabled/SetFileEnabled`、`CurrentStatus`。
- 暂停输出不关闭或重建资源；启动时未创建的输出不能运行期凭空开启。
- 新增稳定错误 7003 `ErrLogControlUnsupported` 和 7004 `ErrLogOutputUnavailable`。
- 默认 Zap Handler 实现可选 `log.Controller`；第三方固定 Handler 无需修改即可继续写日志，
  只有控制接口会返回“不支持”。
- `Application.Diagnostics()` 不再包含日志输出控制状态，避免把管理面配置混入常规诊断快照；
  诊断 JSON 升为 `schema_version: 2`。需要该状态时使用 `log.CurrentStatus()`。

## 迁移提示

既有 v3.0 配置不需要修改。若希望维持旧的完整归属显示，无需显式添加
`context_fields`，默认值已经是两个 `true`。新代码按以下规则选择入口：

```go
// 没有明确 Service 归属的普通代码。
log.Info("cache refreshed")

// Service 或 Module 内，需要自动显示 Node/Service 归属。
target.Logger().Info("player loaded", log.Int64("player_id", 10001))
```

文件启用后实际文件名会增加 Application 前缀；日志采集配置需要从 `origin.log` 调整为
`<app-name>-origin.log`。运行时临时调级后使用对应 Reset 恢复启动配置值。

Diagnostics JSON 和 Go 快照已从 `schema_version: 1` 演进为 `2`：`Snapshot.Log` 与 JSON 的
`log` 字段不再存在。诊断 HTTP 或监控适配器需要按 Schema 2 解析；需要日志状态的管理代码改用
`log.CurrentStatus()`。
