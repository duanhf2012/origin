## Benchmark

命令分别运行三次：

```text
go test -run '^$' -bench 'Benchmark(GlobalDisabled|Disabled|GlobalSyncFields|SyncFields)$' -benchmem -count=3 ./log
go test -run '^$' -bench 'Benchmark(JSONEncoding|TextEncoding)$' -benchmem -count=3 ./log/zaplog
```

下表使用三次结果的中位数；只用于同机比较，不作为跨机器容量承诺：

| 场景 | ns/op | B/op | allocs/op |
| --- | ---: | ---: | ---: |
| 直接 Logger，禁用快路径 | 19.9 | 0 | 0 |
| 包级 Logger，禁用快路径 | 32.3 | 0 | 0 |
| 直接 Logger，同步 + 1 字段 | 1,540 | 632 | 6 |
| 包级 Logger，同步 + 1 字段 | 2,098 | 632 | 6 |
| JSON Handler + 归属/2 业务字段 | 1,613 | 1,201 | 3 |
| Text Handler + 归属/2 业务字段 | 494 | 264 | 2 |

结论：包级原子转发在关闭级别时增加约 12 ns，仍保持零分配；同步完整写入没有增加分配数。
直接文本编码明显低于 JSON 编码成本，适合控制台人工阅读。生产默认仍应使用异步模式。

## 已修正的验收发现

1. 文本字段名包含空格、等号或控制字符时会破坏 `key=value` 边界；先增加失败测试，再改为
   对歧义 Key 使用 Go 字符串引号。
2. `go vet` 发现构造函数按值返回包含 `atomic.Bool` 的状态，会复制 `atomic.noCopy`；改为在
   Console/File 最终字段地址原位初始化，并重新通过测试、竞态和 vet。

## 剩余边界

- 包级默认 Logger 只适合常规“一进程一个 Application”；并行多 Application 测试或特殊
  宿主使用明确实例 Logger，不依赖包级归属。
- 异步队列中尚未处理的记录按处理时最新输出状态过滤；严格控制点测试使用 sync。
- 启动配置关闭的输出没有资源，运行期不能创建；需要动态首次建文件时应另行设计惰性输出。
- 第三方 Handler 只有实现可选 Controller 才能提供运行时控制和 Diagnostics 细分状态。
