# v3.3 RC 发布审查报告

> 日期：2026-08-15
>
> 状态：Windows 发布门禁通过
>
> 目标：v3.3.0 RC
>
> 后续收口（2026-08-25）：Go 1.27.0 已于 2026-08-19 正式发布，当前模块已将工具链门槛从
> `go 1.27rc2` 更新为 `go 1.27.0`。下文 RC 环境与风险描述保留为发布前历史记录。

## 1. 变更范围

本次 RC 将当前工作树统一收口为三项增量：

1. RPC Client 增加 `WhereLabels(map[string]string)` 候选过滤，并继续复用现有单目标路由；
2. 模块工具链门槛切换到 `go 1.27rc2`，为 `Service.DispatchAsyncCompletion[T]` 泛型方法
   补齐成功、等待错误、取消、Deadline、容量拒绝、停止、panic 和非法参数测试；
3. Kafka JSON 在 Sonic v1.15.2 的 Go 1.27 标准库兼容路径下显式保持 `interface{}` 整数
   解码为 int64 的契约，同时拒绝多顶层值、非法 UTF-8 和超出 int64 的整数字面量。

## 2. 审查修正

Kafka 初始兼容实现把所有无法解析为 int64 的 `json.Number` 回退到 float64。审查确认这会让
超出 int64 的纯整数字面量在成功返回时静默丢失精度；现已按词法区分整数和小数/指数，纯
整数溢出返回 `ErrInvalidArgument`，小数及指数仍归一化为 float64。

标准库 `encoding/json` 会替换原始非法 UTF-8，而原配置启用了 Sonic `ValidateString`；现已在
解码前显式验证 UTF-8，避免消息内容被静默改写。第二次 Decode 必须精确到 EOF，防止接受
多个顶层 JSON 值。

RPC Labels 审查确认过滤发生在契约和生命周期之后、Transport 与连接之前；无候选不绕过既有
错误分类，标签匹配但连接断开仍保留 Await 等待恢复。过滤条件有 32 项硬上限，不引入缓存、
候选复制、锁或包级可变状态。

## 3. 工具链与发布约束

Go 1.27 泛型方法是当前 RC 工具链能力，因此 `go.mod` 明确为 `go 1.27rc2`。这意味着 v3.3 RC
使用者必须使用 Go 1.27 RC2 或兼容的更新工具链；Go 1.26 及更早版本会在解析泛型方法时失败。
正式版 Go 1.27 发布后，应在后续提交把工具链门槛从预发布版本收敛到正式版本并重复全仓门禁。

## 4. 覆盖率复核

| 包 | 总语句覆盖率 | 本次重点函数 |
| --- | ---: | --- |
| `rpc` | 59.9% | Labels 核心函数 92.6%～100% |
| `service` | 84.5% | 泛型 `DispatchAsyncCompletion` 100% |
| `sysmodule/kafkamodule` | 78.7% | `DecodeJSON` 100%、尾部校验 100%、数字归一化 92.3% |

Kafka 数字归一化未覆盖的分支是公开解码入口无法产生的非法 `reflect.Value` 等防御路径；正常
Map、Slice、Array、Struct、Pointer、nil interface、nil pointer、整数、小数、指数及溢出路径均
有有效断言。

## 5. 最终门禁

环境：Windows amd64，Go 1.27rc2。以下门禁全部通过：

```text
go test ./rpc ./internal/rpcgen ./service ./sysmodule/kafkamodule \
  ./tests/contracts ./tests/integration/rpcfixture -count=1
go test -race ./rpc ./internal/rpcgen ./service ./sysmodule/kafkamodule -count=1
go test -race ./tests/integration/rpcfixture \
  -run TestM19TCPGeneratedBindingRoutesAcrossRunningInstances -count=1
go test ./... -count=1
go vet ./...
go build ./...
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build ./...
go run ./cmd/origingen rpc --check ./...
go mod tidy -diff
git diff --check
```

Kafka 与泛型完成回调的重点用例另以 `-count=20` 重复通过。Go 1.27rc2 由 Go 自动工具链
选择；格式化使用同一 GOROOT 下的 `gofmt`，避免系统 PATH 中较旧 gofmt 不识别泛型方法。

## 6. 剩余发布风险

- Go 1.27 当前仍为 RC，v3.3 RC 明确接受预发布工具链风险；正式版发布后需要升级门槛并
  重复门禁；
- 本轮完成 Windows 原生测试和 Linux amd64 无 CGO 交叉构建，未执行 Linux/macOS 原生运行；
- RPC 网络标签路径已由 Windows 真实双 Node TCP Race 用例覆盖，但端到端 P95/P99 仍应在
  目标 Linux 发布环境持续观测。

除上述已声明的 RC 与平台验证边界外，本轮审查没有遗留已知阻断问题。
