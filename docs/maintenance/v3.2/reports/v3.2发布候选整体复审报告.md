本轮没有为了形式统一继续重构，也没有增加兼容层、对象池、第二层队列或未经 Profile/Benchmark 证明的
性能优化。MySQL Module 仍按已确认优先级暂缓，未授权 Proposal 不计为功能遗漏。

“通过”表示当前功能、配置、平台和测试范围内没有已知缺陷，不代表数学意义上的绝对零 Bug。正式对外
发布仍需先处理第 7 节两项版本与许可证元数据。

## 2. 审查顺序与范围控制

1. 以当前人工确认的公开代码外观为事实源，设计文档与代码冲突时先按代码判断，再修正文档；
2. 以 `5e7a5ae` 为 v3.1 实际复验边界，深审其后的 38 个 v3.2 提交；
3. 先检查外观、生命周期、并发、资源所有权和正确性，再检查覆盖、性能、教程和发布元数据；
4. 设计优化只处理当前功能的真实问题；已有设计正确、职责清晰且测试充分时保持现状；
5. 性能只接受已有 Benchmark/Profile 支持的必要改动；现有网络、Kafka、Redis 和 Blueprint 证据不支持
   再增加对象池、Worker Pool 或额外队列；
6. 本地普通测试与真实依赖测试分开执行；外部服务测试使用 Ubuntu 保留环境且不删除容器。

## 3. 复审中发现并关闭的问题

### 3.1 RPC 生成文件跨平台换行漂移

Windows `core.autocrlf=true` 会让 `git archive` 或首次 Checkout 把 `*.rpc.gen.go` 转成 CRLF，而生成器在
Ubuntu 输出 LF。结果是 Windows 看似通过，Ubuntu `TestCheckedIntegrationGenerationIsCurrent` 必然报告
生成文件过期。

修复为在 `.gitattributes` 中固定 `*.rpc.gen.go text eol=lf`。两份生成文件归一化后，Windows 连续 10 次
生成一致性检查、Ubuntu 全仓生成检查以及全仓 `origingen rpc --check` 均通过。

### 3.2 MongoDB 教程重复运行事务超时

`GrantRewardOnce` 原先在事务内遇到唯一奖励 ID 冲突后直接返回 `nil`。MongoDB 已将该事务标记为中止，
Driver 随后 Commit/Retry，导致第二次运行教程稳定耗尽 Origin 默认 15 秒 Await Deadline。

修复后，重复键错误先退出事务并完成 Abort，再在事务外映射为“奖励已经发放”的幂等成功；完整教程显式
使用 60 秒演示预算，并为各业务步骤增加错误上下文。真实 Replica Set 回归测试连续执行两次，验证金币只
增加一次；完整 Example 连续运行两次均成功。

### 3.3 已知可达依赖漏洞

扫描发现 Gin 引入的间接依赖 `quic-go v0.59.0` 命中 `GO-2026-5676`（HTTP/3 QPACK Trailer 内存耗尽）。
仅升级到修复补丁 `v0.59.1`，没有跨次版本或改变 Origin 外观。Windows、Ubuntu 二进制扫描均为 0 个可达
漏洞。模块图仍提示 `x/crypto/openpgp` 不维护，但当前二进制没有导入或调用该包，记录为不可达剩余风险。
