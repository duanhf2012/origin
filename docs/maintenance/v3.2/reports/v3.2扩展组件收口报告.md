## 4. 后续建议

下一阶段不应直接继续叠加功能。建议先冻结 v3.2 候选提交，执行一次面向发布的整体审查：依赖与许可证、
公开 API 清单、全仓覆盖率缺口、教程从零运行、真实外部依赖恢复、安装部署和版本标识。该审查若发现问题，
按“设计/公共外观 → 生命周期与正确性 → 测试 → 性能 → 教程”的顺序处理；性能改动仍必须由 Profile 或
Benchmark 证明必要性。
